    16 — Competitive Roadmap (S15–S36)

    Re-planned 2026-10-09 at the owner's request after the framework coverage review (doc 17): framework design and mixed-framework flows move ahead of Ship to users and RAG, and the owner's builder fixes become S17. §7 is the current order; §6 keeps the original scoring for reference.

    Approved by the owner on 2026-10-07. This order replaces the S15–S19 plan from the Copilot plan v2 and the "S20+ GA backlog" row of the sprint plan. Live, editable copy: AgentCanvas competitive roadmap (Claude Doc).

    1. Summary

    After S14 (AI Copilot I, merged in #15), the next three sprints are cheap, high-value wins: make every workflow callable over MCP and A2A, add integrations through an MCP connector gallery, and let any framework's agent run as a node on the canvas. That last one gives AgentCanvas working support for every popular open-source agent framework by S16, before full per-framework authoring lands.

    • Ranking rule: each candidate gets a value score (1–5, from the market gaps in §3) and an effort in sprints; the plan runs the highest value per sprint first, with a +1 bump for multi-framework work because it is the product's core promise.
    • Multi-framework in three tiers: every framework gets Interop in S16; from S20–S22 (re-plan of 2026-10-09) the canvas designs single agents in every framework and mixes them in one flow, then the most-used frameworks get whole-flow authoring and code export one by one, in order of adoption (§4).
    • Unique feature it unlocks: compile one workflow to two or more frameworks and compare quality, cost and latency side by side in Evaluation Studio (S25). No competitor found offers this.
    • Every sprint keeps the standing rule: review the whole codebase for errors first, merge when done, version tags are left to the owner.

    3. Market gaps

    Buyers in 2026 rank governance, quality and observability first, where AgentCanvas is already strong; it is behind on reach (integrations, interop, end-user surfaces) and on RAG.

    What buyers or users want Evidence (search summaries) AgentCanvas today Gap
    Security and governance 34% name it the top platform factor; 32% name quality the top barrier (CrewAI survey) Orgs, roles, OIDC, audit, CEL policies, Evaluation Studio, release gates Small: guardrails (PII, prompt injection, moderation)
    Observability teams trust Only a third of teams satisfied (Dynatrace) Traces, metrics, online evals, drift alerts Small: export to Langfuse, Phoenix, Datadog
    Integrations n8n 400+; Dify and n8n expose and consume MCP (Dify 1.6) HTTP and MCP tool nodes, no gallery Large
    Framework choice LangGraph carries most real usage (~68% of agent-framework downloads) while CrewAI, AutoGen, Agno and others hold large communities (keenable) LangGraph only; adapter SPI and 10 adapter specs written Large: the core promise is unbuilt
    RAG and knowledge bases Dify's main draw pgvector memory, no ingestion studio Large
    Ship to end users Dify apps, OpenAI ChatKit, Copilot Studio channels API-key endpoints, webhooks, cron Medium: no chat widget or share page
    Describe-it-and-build-it assistant Copilot Studio, n8n, Sim Studio Copilot I shipped in S14 Closing
    Fast start Template galleries everywhere A few templates, guided build Medium

    Exact figures are approximate: the pages were not opened (the build environment's proxy blocks most vendor sites).

    4. Multi-framework strategy

    Builds on doc 11, doc 12, the adapter SPI in apps/api/agentcanvas/adapters/spi.py and the adapter specs; it does not redesign them.

    Tiers (doc 11 §7): Interop — the framework's agent runs as a node (Wrapped Agent, remote A2A agent or MCP agent node), cheap and covers every framework at once · Authoring — idiomatic codegen, deploy, tracing, limited step debugging · Full — authoring plus live debugging, approvals, persistence, evals and import.

    Framework Interop Authoring or Full Sprint Why this order
    LangChain / LangGraph / Deep Agents Done Full, done — Most real-world usage
    OpenAI Agents SDK S16 Agent design S21; flows and Full (agent tier) S25 S21, S25 Large user base; smallest adapter; unlocks convert-and-compare
    Pydantic AI and Agno S16 Agent design S21; flows Authoring S32 S21, S32 Fast-growing, cheap at Authoring tier; Agno is new to the adapter list
    CrewAI S16 Agent design S21; Full for Flows, Authoring for Crews S27 S21, S27 Biggest multi-agent community; moved ahead of Microsoft and ADK
    Google ADK S16 Agent design S21; flows Full S29–S30 S21, S29–S30 Enterprise reach through Google Cloud
    Strands and LlamaIndex Workflows S16 Agent design S21; flows Authoring S35 S21, S35 Smaller share; LlamaIndex pairs with Knowledge Studio
    Microsoft Agent Framework (AutoGen's successor) S16 Agent design S21; flows Authoring, Full later S21, S33–S34 Covers AutoGen users and .NET-leaning enterprises
    Mastra (TypeScript) S16 via MCP or A2A Authoring S36 Needs a Node.js sidecar host
    Claude Agent SDK S16 Agent design S21 S21
    AG2, smolagents, Semantic Kernel, Haystack, DSPy, Vercel AI SDK, .NET and Java frameworks S16 Interop only (wrapped, A2A or MCP) until users ask — Wrapped or remote is enough until demand shows
    • Portable core plus native extras: core blocks compile to any framework; framework-only blocks are marked, and a portability check says which frameworks a workflow can target.
    • Mixed flows (S21, S28): each agent on the canvas picks its framework; the flow runs in the LangGraph host with the other frameworks' agents in process (A2A for other languages), and S28 exports and deploys such a flow as one project with typed boundaries between the parts.
    • Full depth only for the top three (OpenAI Agents SDK, CrewAI, Google ADK); the rest stop at Authoring until users ask, because each adapter spec sizes Full at 12–24 team-weeks.
    • Convert and compare: from S25, one click recompiles a workflow for another framework and Evaluation Studio runs both on the same dataset.
    • Same platform services for all: runs, inbox, triggers, versions, evals, policies and deployments stay framework-neutral, so each adapter inherits them.

    5. Changes to the owner's ideas

    1. "Support all frameworks" becomes "every framework runs from S16, the top ones go deep": equal depth for ten frameworks would take years and produce a lowest-common-denominator canvas.
    2. Multi-framework is a feature, not a checkbox: convert-and-compare uses the Evaluation Studio already built.
    3. Integrations come through a curated MCP connector gallery instead of hand-built connectors.
    4. Every workflow becomes a tool others can call (MCP and A2A endpoints, old S17, moved to S15).
    5. The Copilot is framework-aware (started in S14, #15).
    6. The two beginner sprints merge into one (S23), paired with importers from Langflow, Flowise and n8n.

    8. Risks and open questions

    • Framework churn: pinned versions per adapter, nightly upstream checks, adapter versions separate from the core.
    • Estimates: the adapter specs size each adapter for a team over 12–24 weeks; one or two sprints here assume the pace of S9–S14 and may stretch.
    • Re-plan cost (2026-10-09): Ship to users and Knowledge Studio move back six and four sprints to make room for S17 and S20–S22.
    • Interop is not authoring: wrapped agents are black boxes on the canvas (no per-step debugging inside them); docs and badges must say so.
    • Open question: a hosted cloud trial is the biggest adoption lever but means running paid infrastructure. Owner's call; not scheduled.
